# Decision Log — Simple Todo App Brief

## 2026-05-22

### D1: Learning is the primary goal
**Decision:** BMad process mastery takes priority over app feature completeness.
**Reason:** User's stated goal is to become fluent in BMad Method so they can run it independently on future projects. The app is the vehicle, not the destination.

### D2: Success criterion defined
**Decision:** Success = user can open Claude Code, run the BMad agents end-to-end, and produce full planning artifacts through to development without external tutorials or hand-holding.
**Reason:** User articulated this explicitly when pushed for a concrete answer.

### D3: Reminders are the core value proposition
**Decision:** The app's primary job is combating forgetfulness via timely reminders — not task organization.
**Reason:** Established in brainstorming session (First Principles Thinking). User is phone-reliant and practical.

### D4: Voice input with AI parsing is in scope (v1)
**Decision:** Voice-to-task with natural language parsing (e.g. "remind me to call mom tomorrow at 6pm" → parsed name + deadline). Confirmation screen required before saving.
**Reason:** User identified this as the feature that would make them actually use the app over Apple Reminders / Google Tasks. AI integration considered low-effort. Confirmation screen assumed by user — prevents bad saves from misparsing.

### D5: Single-user only for v1
**Decision:** No authentication, no multi-user accounts.
**Reason:** User initially hedged ("if it's simple"). Pushed back on scope creep risk. User agreed single-user keeps architecture focused. Browser-based access from any device still possible without auth.

### D6: Recurring tasks are in scope
**Decision:** Recurring task support included in v1.
**Reason:** User confirmed when offered as a candidate feature. Natural fit for a reminder-first app.

### D7: Explicit out-of-scope items
**Decision:** The following are explicitly excluded from v1:
- Collaboration / task sharing
- Categories, tags, priorities
- Multiple lists / projects
- Calendar sync (Google, Apple)
**Reason:** User confirmed each when offered as candidates. Scope is intentionally narrow to support the learning goal.

### D8: App vision
**Decision:** Portfolio piece + personal productivity tool. No commercial ambitions.
**Reason:** User explicitly stated the todo space is saturated and has no plans to productize. Honest framing preserved.

### D9: Tech stack (from brainstorming)
**Decision:** React (frontend) + FastAPI/Python (backend). Push notifications for reminder delivery. Preset reminder offsets: 15 min, 30 min, 1 hr, 1 day, 2 days before deadline. Multiple reminders per task supported.
**Reason:** Established in brainstorming session. Not revisited — user anchored on this stack.
